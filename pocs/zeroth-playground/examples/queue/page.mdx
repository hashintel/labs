A transition at rate $\lambda$ fires within a step of length $\Delta t$ with probability $1 - e^{-\lambda \Delta t}$. The compiler turns that into a coin: an input draw `u_T` and the test `X(u_T) >= θ`, with $\theta = e^{-\lambda \Delta t}$ computed at compile time.

Over a step of 0.5, `Arrive` at rate 2.5 gets $\theta = e^{-1.25} \approx 0.29$, so it fires in about 71% of steps:

```python
return (Waiting + 1.0 <= 4.0) & (X(u_Arrive) >= 0.2865047968601901)
```

The first term is the capacity of `Waiting`, four tokens. The draws are Reals, so the places are Reals too and the modules use the theory LRA: `Waiting = Var(REAL)`, `Waiting + 1.0`.

### Options

- **Time step** sets $\Delta t$, and every threshold follows it.
- **Marking** on Int keeps the places Int and moves each draw into an LRA module, `Draw_Arrive`, that writes a Bool `hit_Arrive`. The guard reads `X(hit_Arrive)` in place of the draw.
- **Rates** on clock refuses the net with `clocks-capacity`, because of the cap on `Waiting`.
